# ImShark 0.8.2

ImShark is a Dear ImGui desktop packet analyzer for capture files and live network traffic.

## Changes

This patch includes the v0.8.0 modernization, the MSVC build fix and the GCC sanitizer test-fixture correction before publishing the complete cross-platform package set.

- Fix the lifetime of SCTP test payloads found by GCC AddressSanitizer; retain the retransmission checks.
- Separate vcpkg cache entries by runner image and build preset so a minimal build cannot occupy a full-build cache entry.
- Initialize compact link-layer facts in the packet constructor for compatibility with MSVC, preserving zero defaults and the per-packet size budget.
- Reuse compatible vcpkg binary archives across release version bumps; vcpkg still checks each dependency's ABI before reuse.

- Bring default C/C++ dependencies under a pinned vcpkg manifest, including Dear ImGui 1.92.9b and its GLFW/OpenGL3 backends. Remove vendored dependency copies.
- Prevent capture exports from overwriting their input, bound clipboard selections and report capture-loading/settings errors cleanly.
- Add `--help`, `--version`, command-line argument validation and capture-aware window titles.
- Fix portable NFS timestamps and GCC diagnostics; support Release, debug/sanitizer and minimal build presets.
- Refresh the README and developer/user guides with a real Linux screenshot and reproducible Docker verification.
- Build only on version tags and publish tested application packages with SHA-256 checksums under the same tag.

## Downloads

| System | Package |
|---|---|
| Linux x86_64 | AppImage, DEB or tar.gz (Ubuntu 24.04 baseline) |
| macOS Apple Silicon | DMG |
| Windows x86_64 | ZIP |

Compare your download's SHA-256 digest with `SHA256SUMS.txt`. Linux and macOS support libpcap live capture with the required device permissions. The Windows package supports offline capture analysis; live capture needs a separate Npcap-enabled build. The macOS application is ad hoc signed, without Developer ID signing or notarization.

All platform Release builds run CTest before packaging. Publication also requires sanitizer/minimal regressions and the Linux Docker test, which opens the sample capture with Mesa software OpenGL and verifies the installed DEB in a clean Ubuntu image. Linux screenshots and logs are available in the associated Actions run.
